## Version 3.1 — Current Release

### Capability Log

#### Presentation Layer

**Non-blocking Font Loading.** The Google Fonts `<link>` tag now uses the `preload` / `onload` pattern to avoid a 3-second rendering hang in offline or air-gapped environments. A `<noscript>` fallback ensures the font loads in environments where JavaScript is disabled for resource hints.

**Section Collapse Animation.** Section bodies now animate open and close via CSS `grid-template-rows` transition (`0fr` ↔ `1fr`), replacing the previous height-based approach that caused layout reflow. The toggle state is managed by toggling the `.collapsed` class; no inline style manipulation is performed by JavaScript.

**Help Panel Architecture.** The `#help-panel` element is now declared as static HTML in the `<body>` rather than being dynamically generated by `renderHeader()`. The `boot()` function moves it into its correct DOM position (after `.masthead`) on each load. This prevents the panel from being regenerated and losing event state on theme switches.

**SVG Icon Rendering.** All `<symbol>` elements in the SVG sprite now carry explicit `viewBox` attributes. The `icon()` helper renders each `<use>` element with explicit `width="13" height="13" viewBox="0 0 24 24"` attributes, ensuring consistent icon rendering across all tested browsers including Safari.

**Delta Inversion Logic.** KPI tiles where an upward movement is beneficial (e.g., SLA Compliance) now support `"invert_delta": true`. The renderer applies the correct colour (`green` for improvement, `red` for decline) regardless of the raw `delta_dir` value.

**Error Overlay.** Boot-time data loading errors now render a styled, user-readable error overlay rather than a blank screen. The overlay provides the HTTP error message, the correct Python server launch command, and a reference to the Launcher.

#### Data Editor

**`snow_editor.html`** provides a companion GUI form for editing `snow_weekly.json` without using a text editor. It reads `snow_config.json` for field validation rules, allowed values, and valid state/priority mappings, and writes a validated JSON output for the Data Steward to save.

#### Portable Compiler

**UTF-8 Without BOM.** The compiler explicitly uses `[System.Text.UTF8Encoding]::new($false)` when writing the portable output file, eliminating BOM prefix bytes that caused parsing artefacts in some browser and text-processing environments.

**Singleline Regex for Fetch Block Patch.** The `[System.Text.RegularExpressions.RegexOptions]::Singleline` flag is applied when matching the `PORTABLE_FETCH_BLOCK_START/END` delimiters, correctly capturing the multi-line async `fetch()` block.

**Port Iteration.** The launcher iterates ports 8080–8120 sequentially, checking each with `netstat` before attempting to bind. If no port is available in this range, the user receives an actionable error message.

**Style Lookup Safe Defaults.** All colour key lookups in the renderer (`badgeStyle`, `pillStyle`, `trendStyle`, `tagStyle`) return a safe muted fallback for unknown keys and emit a `console.warn` with the unrecognised key name, rather than throwing a runtime error.

**Section Guard.** The `boot()` function guards the `sections` object iteration to skip non-object keys (e.g., `_comment` strings), preventing a crash if annotation keys are present in the JSON.

**Internet Explorer 11 is explicitly unsupported and programmatically incompatible.** IE 11 does not implement CSS Custom Properties (the entire visual design system fails), ES2020 syntax (the renderer throws a parse error before execution), or Chart.js 4.x (which requires a Canvas2D API level unavailable in IE 11). No compatibility shim or polyfill is provided or planned. All managed corporate browser deployments are expected to run a Chromium-based browser at version 90 or later.

## Explicit Out-of-Scope Mandates

The following capabilities are **omitted by deliberate architectural decision** and will not be added without a formal architecture review:

**No Cloud Integration.** The dashboard does not connect to ServiceNow's REST API, any cloud storage service, or any external data endpoint. Data ingestion is exclusively manual, via weekly CSV/Excel export and JSON update. This is a security and air-gap compliance requirement, not a technical limitation.

**No Concurrent Write Locking.** The system has no mechanism to detect or prevent simultaneous editing of `snow_weekly.json` by two users. This is enforced procedurally via the LOCK broadcast protocol (see `DATA_GOVERNANCE.md` §3.3). Implementing a file-lock mechanism would require a server-side runtime, which violates the zero-backend constraint.

**No Automated History.** The application does not maintain version history of data files. All archiving is manual and follows the naming standard in `DATA_GOVERNANCE.md` §4.1. Automated history tracking would require a database or version control integration.

**No Push Notifications.** There are no background service workers, WebSocket connections, or browser notification APIs. The dashboard is a point-in-time rendering of the weekly data file. Live operational alerting is handled via ServiceNow's own notification engine.

**No Multi-Workstream Selector.** The dashboard renders a single portfolio view per JSON file. Separate workstream-level dashboards require separate JSON files and separate Launcher invocations.

**No Real-Time Data Refresh.** The `fetch()` call in `boot()` runs once on page load. There is no polling interval, WebSocket subscription, or server-sent events integration. Refreshing the browser re-fetches the JSON file; this is the intended update mechanism in live server mode.
